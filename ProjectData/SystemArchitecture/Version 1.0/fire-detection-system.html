สถาปัตยกรรมระบบตรวจจับอัคคีภัยในสภาพแวดล้อมที่มีฝุ่นหนาแน่น — คอมพิวเตอร์วิทัศน์เชิงปริภูมิ–เวลา ร่วมกับ Thermal, CO และ PM เพื่อประเมินความเสี่ยงและควบคุมการแจ้งเตือน

01 ภาพรวมระบบ02 Fast Loop03 Fusion Loopหมายเหตุการออกแบบ

ภาพรวมแยกงานพัฒนาโมเดลบน PC ออกจากการทำงานหน้างาน โดย Raspberry Pi 5 เป็นศูนย์กลางประมวลผล และส่งสถานะไปยังอุปกรณ์แจ้งเตือนพร้อมบันทึกเหตุการณ์และแสดงผล

รวมการจัดแนวและประสานเฟรมเป็นจุดเดียวในภาพขยาย ตำแหน่งที่รันแต่ละขั้นระหว่าง OAK-D กับ host ต้องกำหนดให้ตรงกับ DepthAI pipeline ที่พัฒนาจริง; Hailo รับผิดชอบ inference ส่วน Tracking และ Feature Extraction อยู่บน CPU

รับหลักฐานต่างอัตราผ่านหน้าต่างเวลาและตรวจความพร้อมของข้อมูลก่อนรวมหลักฐาน การเทียบ Thermal IoU ต้องจัดพิกัด Thermal ให้สัมพันธ์กับ RGB ซึ่งเพิ่มเป็นเงื่อนไขการเชื่อมต่อเพื่อให้ขั้นตอนในข้อเสนอทำงานได้

การตัดสินใจตามข้อเสนอ

สถานะที่เอกสารระบุ: Normal, Dust Event, Light Interference, Suspicious, Warning, Critical, Alarm ภาพนี้แสดงเป็นโมดูล FSM โดยไม่สมมติกฎ transition ว่าทุกเหตุการณ์ต้องผ่านทุกสถานะตามลำดับ

เริ่ม Temporal Smoothing ด้วย EMA และพิจารณา Kalman เป็นขั้นสูง ส่วน threshold ของ FSM และ sliding window ใช้หน่วยวินาที อัตรา 15–30 Hz เป็นเป้าหมายการออกแบบจากเอกสาร ยังไม่ใช่ผล benchmark

กำหนด BPA, trust / reliability และ threshold ด้วยข้อมูลทดลองจริง ตรวจสอบข้อมูลขาดหายหรือหมดอายุเพื่อไม่ตีความการไม่มีข้อมูลเป็นหลักฐานว่าไม่มีไฟ

ปรับจากภาพโครงเดิม

  • รวมกล่อง Depth Align / Frame Sync ที่ซ้ำกัน และรวมชุดเซนเซอร์เข้ากับ MCU ในภาพรวม
  • เพิ่ม Feature Buffer เพื่อแยก Fast Loop และ Fusion Loop ตามหัวข้อ 4.5
  • ขยาย Fusion เป็นการเตรียม BPA, จัดการ conflict, DST และ Pignistic Transform ก่อน smoothing / FSM
  • เพิ่ม LED / buzzer และเส้นทางข้อมูลสดสู่ Dashboard พร้อมฐานข้อมูลสำหรับประวัติเหตุการณ์
  • คง PC training เป็นงาน offline; แบบจำลองที่ deploy และ post-processing ต้องทดสอบกับ toolchain จริง
